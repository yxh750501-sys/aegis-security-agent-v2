# AEGIS (이지스) 7일차 시연과 확인 범위

이 문서는 2026-10-26(한국 시간)에 공유된 Windows 화면과 실행 기록, 현재 원문을 바탕으로 만든 시연 안내입니다. **시연 대본이나 코드 확인은 새로운 PC에서의 실행 성공 증명이 아닙니다.** 기존 학생 제출물과 프로젝트 폴더는 보존합니다. 최종 과제 제출은 별도로 GitHub 저장소 주소와 제출 커밋의 40자리 SHA로 진행합니다.

| 저장소 | `https://github.com/yxh750501-sys/aegis-security-agent-v2` |
| 공유 화면의 작업 커밋 | `9bbe9a7fa6f46f591a5081d124ea836ee50d9bbb` (`main`, 당시 작업 트리 깨끗함). 이 문서를 추가한 뒤의 최종 커밋에서 Windows 시연을 다시 했다는 뜻은 아님 |

| 미연결·확인 불가 | 공유 화면의 `SDP 미연결`, 기존 서버·에이전트 연결 실패. 실제 업무 앱 판정·XDR 사건·AI 호출·보안 조치·패키지 설치 결과는 확인되지 않음 |

공유 화면에는 실제 로컬 조회로 표시된 CPU `33.9%`, 메모리 `9.8 GiB / 15.9 GiB`, 디스크 남은 공간 `14.42 GiB / 464.68 GiB`와 채집 시각 **2026-10-26 오후 4:36:31**이 보였습니다. 이후 학생 표시의 조회 시각이 **오후 4:36:53**으로 갱신되고 CPU `23.2%`로 달라졌습니다. 이 값은 당시 화면의 관찰 기록이며 고정된 성능 수치가 아닙니다. 공유 화면의 System 경고 6건·오류 4건, Application 경고 4건·오류 8건은 **Windows 로그 개수이지 침해나 공격 탐지 결과가 아닙니다.** 화면의 네트워크 주소와 개인 폴더 경로는 이 문서에 옮기지 않았습니다.

## 핵심 기능 3가지와 제공·추가 범위

| 핵심 기능 | 시작 틀·제공 경로 | 직접 구현하거나 개선한 부분 | 시연에서 확인할 결과 |
|---|---|---|---|
| 1. 보호 현황과 내 PC | `public/index.html`, `public/app.js`, `src/server.mjs`의 화면·요청 연결, 기존 신원·기기·세션 원천 경로 | `src/pc-status.mjs`의 로컬 CPU·메모리·디스크 읽기, `src/local-security-status.mjs`의 읽기 전용 네트워크·방화벽·Windows 기록 조회, `student/extension.mjs`의 상태 구분과 키보드로 누를 수 있는 다시 조회 | 로컬 값·단위·채집 시각 표시와 새로 읽는 중 상태. 기존 서버 신원은 미연결이므로 실제 사용자·기기·세션은 확인 불가 |
| 2. 업무 앱 접근 판정 | 제공 UI의 앱 요청과 서버·SDP 판정 경로 | `student/extension.mjs`의 `renderDecision`이 판정·이유·오류 상태를 구분해 표시 | 메뉴와 연결 실패 안내를 보여 줌. 실제 허용·거부·추가 확인 판정은 시연하지 못함 |
| 3. 보안 기록과 XDR 경보 | 제공 UI의 기록 요청·선택과 서버·SDP 사건 경로 | `student/extension.mjs`의 `renderEvents` 목록·필터·상세 표시, 로컬 Windows 기록 건수의 별도 표시 | 메뉴와 연결 실패 안내, 로컬 Windows 경고·오류 건수를 보여 줌. 실제 XDR 사건 목록·경보는 확인하지 못함 |

학생 표시 함수의 범위와 데이터 흐름은 [학생 실행 설명서](STUDENT_RUNBOOK.md), 실제 화면 연결은 [`public/app.js`](../public/app.js), 학생 표시 구현은 [`student/extension.mjs`](../student/extension.mjs)에서 다시 확인할 수 있습니다. 로컬 PC 정보는 [PC 조회 코드](../src/pc-status.mjs)와 [읽기 전용 Windows 조회 코드](../src/local-security-status.mjs)가 앱 서버에서 읽습니다. 방화벽 설정은 변경하지 않으며 권한이나 서비스 문제로 읽지 못하면 `확인 불가`와 이유를 표시합니다.

## 처음부터 끝까지 보여 주는 순서

1. 아래 명령으로 대상 커밋과 작업 상태를 확인하고 **제공 실행 도구**로 앱을 켭니다. 서버 창을 열어 둡니다. 서버 응답 문구만으로 SDP·AI 연결 성공을 주장하지 않습니다.
2. 브라우저에서 `http://127.0.0.1:5189/`을 열어 **보호 현황 → 업무 앱 → 보안 기록**의 세 메뉴를 보여 줍니다.
3. 보호 현황에서 **내 PC 상태**의 CPU·메모리·디스크와 각 채집 시각, **연결과 Windows 기록**의 네트워크·방화벽·System·Application 조회 시각을 보여 줍니다. 로그 건수는 공격 탐지 결과가 아니라는 문구를 읽어 줍니다.
4. 학생 상태·알림 표시의 `다시 조회`를 `Tab`으로 선택하고 `Enter`로 누릅니다. `새로 읽는 중…`을 보여 준 뒤 새 조회 시각을 확인합니다. 공유된 Windows 화면과 사용자 확인에서는 이 동작이 성공했습니다.
5. 별도 `SDP 미연결` 표시를 확인합니다. 이어 업무 앱의 판정 불가·연결 실패, 보안 기록의 조회 실패를 보여 주고, **빈 결과나 실제 판정 성공으로 설명하지 않습니다.** 사건을 고를 수 없으므로 실제 AI 사건 설명·조치는 시연하지 않습니다.
6. 아래의 포장·운영 연결 한계를 밝히고 서버 창에서 `Ctrl+C`로 종료합니다. 시연 후 최종 커밋과 결과를 기록합니다.

## 같은 결과를 다시 확인하는 방법

Windows PowerShell을 **실제 Git 복제본의 `on-client` 폴더**에서 엽니다. `on-client`가 아닌 다른 폴더나 오래된 Workbench 복제본에서 실행하지 않습니다. 다음 명령은 PC 보안 정책을 전역으로 바꾸지 않습니다.

```powershell
git rev-parse --show-toplevel
git rev-parse HEAD
git status --short --branch
node --version
npm.cmd run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

`git rev-parse --show-toplevel`은 의도한 복제본의 최상위를, `git rev-parse HEAD`는 시연할 **현재 소스의 40자리 SHA**를 보여 줘야 합니다. 미커밋 파일이 있으면 삭제하거나 덮어쓰지 않습니다. `npm.cmd run check`는 학생 파일 문법 검사일 뿐 전체 기능의 성공 증명이 아닙니다. 제공 실행 도구가 주소를 출력하면 서버 창을 열어 둔 채 브라우저에서 `http://127.0.0.1:5189/`을 열고 위 2~5번을 확인합니다. 포트를 바꿔 실행했다면 브라우저 포트도 맞춥니다. 현재 소스를 새 커밋으로 변경하거나 병합한 뒤에는 **그 새 SHA로 Windows 재실행을 별도로 기록**해야 합니다.

**실행 패키지 경로: 미확인.** `APP_PACKAGE_MANIFEST.json`, `INSTALL.md`, 승인된 host 바로가기와 설치 결과도 생성·검증하지 않았습니다. `PROVIDED_RUNTIME_NOT_INSTALLED`나 운영 앱 승인 키 오류는 실제로 관찰된 오류가 아니며, 그런 오류가 나오면 담당자 준비 항목으로 남깁니다. 소스 커밋과 패키지의 동일성 역시 확인 불가입니다. 패키지가 만들어지면 출력 폴더의 존재·manifest·INSTALL.md 원문과 승인된 실행 순서를 그때 확인합니다.

이 문서의 화면 관찰은 사용자가 제공한 자료에 근거하며 화면 이미지 자체는 저장소에 넣지 않았습니다. 시연용 캡처를 따로 보관한다면 토큰·개인 폴더 경로·사용자 이름·내부 주소를 가리고, 캡처의 대상 커밋과 한국 시간 조회 시각을 함께 적습니다. 도움을 받은 범위는 AI의 실행 안내·문서 정리, 동료의 첫 사용 관찰, 담당자의 포장 환경 안내 대기로 구분합니다. 외부 SaaS 비용·운영 계정·별도 설치 프로그램은 확인하지 않았습니다.
