## 이동 가능한 구성과 재현 순서

원래 작업 폴더나 개인 설정을 복사하지 않고 **새 빈 폴더**에 저장소를 내려받았다. Git 최상위의 `on-client/`에 앱·문서·비밀 없는 [.env.example](../.env.example)이 있다. `package.json`에 외부 npm 의존성이 없고 이 커밋에는 추적된 `package-lock.json`이 없으므로 이번 재현에서 `npm install` 또는 `npm ci`를 실행하지 않았다. 특정 PC의 절대 경로는 실행 전제 조건이 아니다.

`git ls-files`로 `student/extension.mjs`, `docs/STUDENT_RUNBOOK.md`, `.env.example`이 추적됨을 확인했다. 실제 `.env`, 개인 인증 자료, 기존 조치 DB 및 미커밋 작업은 이 커밋의 추적 파일에 없다. Git 복제만으로 이 자료들이 옮겨진다고 가정하지 않는다.

실제 Linux 재현 명령(새 폴더 이름은 원하는 빈 경로로 바꿀 수 있다):

```bash
git clone https://github.com/yxh750501-sys/aegis-security-agent-v2.git /tmp/aegis-stage22-repro
git -C /tmp/aegis-stage22-repro switch --detach 96c3b9336271d7fd6473783219e2c98707c39a7f
git -C /tmp/aegis-stage22-repro rev-parse HEAD
cd /tmp/aegis-stage22-repro/on-client
node --version
npm --version
npm run check
npm start
```

`npm start`가 `케셰브 연결 확인: http://127.0.0.1:5189`를 출력한 뒤 Chromium에서 `http://127.0.0.1:5189/`를 열었다. 실행 터미널에서 `Ctrl+C`로 종료한 뒤 같은 폴더에서 다시 `npm start`를 실행했다. 별도로 `npm run demo`도 시작·종료했다. 기본 실행과 demo 실행은 서로 다른 프로세스로 진행했다. 실제 관찰은 아래 표에 있다.

Windows에서의 이동 절차는 [21단계 학생 실행 설명서](STUDENT_RUNBOOK.md)의 PowerShell 명령을 따른다. 그 설명서에 있는 예전 PC 경로는 예시이며, **새 복제 폴더의 실제 경로**로 바꿔야 한다. 이 Linux 환경에서는 Windows PowerShell과 제공 `tools/start-alekov.ps1` 자체를 실행하지 못했다. 운영자가 발급한 SDP·AI 설정, 인증서, 토큰, 기존 SQLite 데이터베이스를 새 폴더로 복사하지 않았다.

## 새 복제본에서 직접 관찰한 결과

`npm run check`는 `student/extension.mjs` 문법 검사만 수행해 통과했다. 기본 모드에서 로컬 페이지가 HTTP 200을 반환했고 `/api/me`는 `ENGINE_NOT_CONNECTED`, `mode: disconnected`를 반환했다. Chromium에서 **보호 현황**, **업무 앱**, **보안 기록** 탭을 각각 눌렀고, **다시 불러오기** 뒤에도 선택한 탭이 표시됐다. 기본 모드에서는 학생 사용자·기기·기록 영역에 연결 실패 안내가 표시됐다. 서버를 종료·재기동한 뒤 같은 HTTP/API/메뉴 결과를 다시 확인했다.

demo에서는 `연습 사용자`, `practice-user`, `practice-pc`, `practice-session`이 **예제 자료**로 표시됐다. 예제 업무 앱 `library`의 접속 요청에서 `allow`와 예제 정책 이유를 확인했고, 기록 `event-01`의 목록·상세를 확인했다. 이는 실제 회사 계정의 접속 허용이나 XDR 사건 조회 결과가 아니다. AI 요청, OSV 외부 조회, 실제 조치 요청은 하지 않았다.

## 최종 버전에서 남은 확인

- 이 문서가 포함된 **22단계 최종 커밋**의 새 폴더 재현은 별도의 실행 보고서 또는 PR 본문에 실제 SHA와 함께 기록한다. 위 표는 `96c3b9336271d7fd6473783219e2c98707c39a7f`의 1차 관찰만 다룬다. 서로 다른 커밋의 결과를 하나의 최종 소스 통과로 합치지 않는다.
- 실제 Windows PowerShell, 회사 SDP 계정·기기·세션, 운영 XDR, CLCO AI 설명, OSV 외부 조회, 19단계 원천 조치 집행·효과 관측은 **기다림(UNV)**이다.
- 22단계 ALEPH 공식 제출·원문 검토 결과와 운영 인증도 아직 없다. 해당 판정은 코드를 읽는 절차이며 새 환경 실행 증명이 아니다.
- 이 미완료 항목이 남아 있으므로 릴리스 표기는 **검증 중**으로 유지한다. `v1.0` 태그나 완료·운영 가능 표시는 사용하지 않는다.
